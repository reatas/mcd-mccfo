# McCFO 财务模型与计算口径

> 本文件定义 McCFO 三大分析模块的具体公式与口径。所有口径都是**确定性的**——任何一次分析都必须按这里的方法算，保证可复现、可比对。

---

## 一、券资产模型（Coupon as Security）

### 1.1 字段定义

| 符号 | 含义 | 来源字段（示例） |
|---|---|---|
| `D` | 券面额（减免金额，元） | `discount` / `faceValue` / 名称中的"减10" |
| `T` | 使用门槛（最低消费，元） | `threshold` / 名称中的"满30" |
| `E` | 到期日期 | `expireTime` / `validUntil` |
| `N` | 剩余有效天数 = `E` − 今天 | 由 `now-time-info` 推算 |

> ⚠️ 券面金额是「元」字符串，直接用；**不要换算积分**。

### 1.2 券收益率（Yield）

衡量"为了用掉这张券，每 1 元门槛能省回多少"：

```
Yield = D / max(T, D)        # 门槛为 0（无门槛券）时，视为 Yield = 1.0（满额回报）
```

解读：
- **无门槛券**（T = 0）：Yield = 1.0，等于直接打折，价值最高，**优先用**
- **满 30 减 10**：Yield = 10/30 ≈ 0.333
- **满 50 减 5**：Yield = 5/50 = 0.100 → 明显不如上一张

### 1.3 紧迫度（Urgency）

```
Urgency = 1 / max(N, 1)                     # N 为剩余天数
```

- N ≤ 0：已过期（或今天最后一天，需要标注"今天到期"）
- N = 1：紧迫度 1.0
- N = 30：紧迫度 ≈ 0.033

### 1.4 综合优先级（Priority Score）

券的**期望收益** = 能省多少 × 门槛效率 × 时间价值 × 需求匹配：

```
Score = D * Yield * (1 + Urgency) * FitBoost * StorePass
```

| 因子 | 取值 | 说明 |
|---|---|---|
| `D` | 面额（元） | 券的绝对价值——省多少钱是硬道理 |
| `Yield` | 见 1.2 | 门槛效率：无门槛券 = 1.0，满 30 减 10 ≈ 0.333 |
| `(1 + Urgency)` | 1.0 ~ 2.0 | 明天到期 ×2，30 天后到期 ×1.03 |
| `FitBoost` | 1.0 ~ 1.3 | 券的适用范围与用户需求匹配时加分（如用户要买汉堡，汉堡券 ×1.3） |
| `StorePass` | 1 或 0 | `query-store-coupons` 校验后，当前门店不可用的券直接置 0（不参与排序，但保留在表中并注明"本店不可用"） |

排序规则：**Score 降序**。同分时 `D` 大者优先。

> 设计取舍：只按面额排会忽略门槛（满 50 减 15 不一定比满 30 减 10 好）；只按收益率排会让 3 元无门槛券压过 15 元券。乘上 `D` 后，两种错误都被修正——**大额且高效且紧急的券浮到最上面**，这正是"先烧哪张券"的真实答案。

**示例（本仓库样例数据）**：

| 券 | D | Yield | N | Score = D·Yield·(1+1/N)·Fit |
|---|---:|---:|---:|---:|
| 9.9 元中杯冰美式 | 9.1 | 1.000 | 1 | 18.20 |
| 薯薯任选 9.9 元 | 6.1 | 1.000 | 6 | 8.54 |
| 满 30 减 10 | 10.0 | 0.333 | 2 | 5.00 |
| 满 50 减 15 | 15.0 | 0.300 | 10 | 4.95 |

### 1.5 临期预警阈值

| 剩余天数 N | 等级 | 展示 |
|---|---|---|
| N ≤ 0 | ⛔ 已过期 | 灰显，不计入可配置资产 |
| 1 ≤ N ≤ 3 | 🔴 临期 | 单独预警区高亮 |
| 4 ≤ N ≤ 7 | 🟡 关注 | 正常列表但标注 |
| N > 7 | 🟢 充裕 | 正常列表 |

### 1.6 资产汇总口径

```
券资产账面价值 = Σ D_i          （仅统计未过期券）
券资产可动用价值 = Σ D_i        （仅统计未过期 且 当前门店可用）
券资产加权收益率 = Σ (D_i * Yield_i) / Σ D_i
```

## 二、积分资产模型（Points as Cash Equivalent）

### 2.1 字段定义

| 符号 | 含义 | 来源字段（示例） |
|---|---|---|
| `P` | 可用积分余额 | `points` / `availablePoints` |
| `P_exp` | 即将过期积分 | `expiringPoints` |
| `c_j` | 第 j 个可兑换商品消耗积分 | `points`（商城商品） |
| `v_j` | 第 j 个商品的市场参考价值（元） | `cashPrice` / 同类商品标价 |

### 2.2 每积分价值（Value per Point）

```
VPP_j = v_j / c_j          # 单位：元/分
```

这是**积分兑换 ROI 排序的核心指标**：VPP 越高，同样的积分换回的价值越多。

若商品只有「积分价」没有「现金价」，则用**同类商品在菜单中的标价**作为 `v_j` 的代理值，并在输出中标注"估"。

### 2.3 兑换优先级

```
Priority_j = VPP_j * NeedMatch_j
```

| 因子 | 取值 | 说明 |
|---|---|---|
| `NeedMatch` | 0.5 ~ 1.5 | 用户需求匹配度（用户明确想要 ×1.5；通用刚需如咖啡/汉堡 ×1.0；用不上的 ×0.5） |

### 2.4 过期压力（Expiry Pressure）

```
Pressure = P_exp / max(P, 1)
```

- Pressure ≥ 0.3：**高压力**，必须立刻给出"优先兑换清单"，避免积分白白作废
- Pressure < 0.3：正常配置节奏

### 2.5 建议输出口径

```
积分总资产 = P 分
其中即将过期 = P_exp 分（占 xx%）
最优兑换（按 VPP 降序）：Top 3 商品 + 各自 VPP + 建议消耗积分
```

## 三、消费分析模型（Consumption Analytics）

### 3.1 基础指标

```
统计期间     = [开始日期, 结束日期]        # 默认：本月 1 日 → 今天（由 now-time-info 确定）
总支出 S     = Σ amount_i                 # 仅计已完成/已支付订单
订单数 n      = count(orders)
客单价 AOV   = S / n
```

### 3.2 省钱效率

```
原价合计 S_list   = Σ 券前金额
优惠合计 S_save   = Σ (券抵扣 + 活动优惠 + 配送费减免)
实付合计 S_pay    = Σ 实付金额
折扣率 DiscountRate = S_save / S_list          # 越大越省
实付率 PayRate      = S_pay / S_list = 1 - DiscountRate
```

> 口径校验：`S_save + S_pay = S_list`（允许 ±0.01 元四舍五入误差）

### 3.3 结构分析

| 维度 | 分类口径 |
|---|---|
| 品类 | 汉堡 / 小食 / 饮料 / 甜品 / 套餐 / 其他（以 `query-meal-detail` 的品类字段为准） |
| 时段 | 早餐 05:00–10:29 / 午餐 10:30–13:59 / 下午茶 14:00–16:59 / 晚餐 17:00–20:59 / 夜宵 21:00–04:59 |
| 就餐方式 | 到店取餐 / 麦乐送 / 得来速 / 堂食外带 |
| 门店 | 按门店聚合，找"常去店" |

每个维度输出：**金额占比 + 订单数占比 + 环比变化**。

### 3.4 趋势

```
环比 MoM = (S_本月 / S_上月) - 1
```
- 文字描述：**涨（红）** / **跌（绿）**（中文财经习惯，与欧美相反）
- 同时给出"近 4 周周均支出"，避免单月波动误判

### 3.5 榜单

- **TOP 单品**：按出现次数排序（复购王）
- **重仓股**：按该单品累计花费排序
- **最省订单**：折扣率最高的一单（当作"教科书案例"展示）

## 四、活动择时模型（Market Timing）

### 4.1 活动分类

| 类型 | 识别 | 择时含义 |
|---|---|---|
| 会员日 | 活动中含"会员日" | 固定低点，适合聚餐/大额订单 |
| 单品特价 | "9.9 元"、第二份半价 | 适合囤/单独买该单品 |
| 上新 | "新品""限时" | 尝鲜，非必须 |
| 积分活动 | 与抽奖/积分兑换相关 | 配合积分模块一起看 |

### 4.2 择时建议口径

```
今日机会 = 当前进行中 & 与用户常点品类相交 的活动
未来低点 = 未来 7 天内 会员日 / 高力度特价 的日期
```

输出一张"周历表"：周一 ~ 周日 × 当天活动 × 建议动作。

> ⚠️ 表达纪律：可以提示"周三有板烧特价"这类**事实**，但**不得**使用"错过再等一年""不买就亏"等制造稀缺焦虑的话术。

## 五、跨模块总览：个人麦麦资产负债表

当用户要一份"全景"时，用这张表收口：

```
┌─────────────────────────────────────────────┐
│  McCFO 个人麦麦资产负债表（截至 YYYY-MM-DD）   │
├──────────────────┬──────────────────────────┤
│ 资产             │ 价值 / 说明               │
│ 🎫 券资产         │ 账面 ¥xx（n 张，临期 m 张）│
│ 💰 积分资产       │ xx 分（其中 xx 分将过期）  │
├──────────────────┼──────────────────────────┤
│ 本期支出（现金流）│ ¥xx（n 单，客单价 ¥xx）    │
│ 本节省钱          │ ¥xx（折扣率 xx%）          │
├──────────────────┼──────────────────────────┤
│ 待决策事项        │ ①… ②… ③…                │
└──────────────────┴──────────────────────────┘
```

**待决策事项**是这张表的灵魂——不列数据，只列"接下来该做什么"，最多 3 条。

## 六、计算纪律

1. **一切数字可追溯**：每个指标都要能从原始工具返回复算。
2. **缺数据不猜**：某项取不到就标"未取到"，宁可少一个指标也不编。
3. **四舍五入**：金额保留 2 位小数，比率保留 1 位百分数，积分取整。
4. **期间一致**：同一份财报内所有指标必须用同一个统计期间。
5. **口径写在脚注**：财报末尾注明数据来源与期间，例如"数据来源：`order-list`，期间 2026-10-01 ~ 2026-10-10"。
